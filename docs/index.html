Budget Tracker

An AI-forward budget app. Bills-first budgeting from actual cash balances — with a categorization engine that learns your payees, and a data model designed to be read by an assistant, not just clicked by a human.

What it does

Live balances, with receipts

Every account shows when it last synced. A number without a sync time is a rumor — this app treats it that way.

An inbox that learns

New transactions land in an inbox. Categorize once and the app remembers the payee; next time it suggests the category before you tap anything.

Bills-first, not envelope-first

Fixed bills don't need monthly assignment busywork — they get computed statuses from their due dates: Paid (green, with the date), Covered, Short (naming the paycheck that covers it), or On card. Only the categories where you actually decide spending stay manual envelopes.

Safe to spend

One headline number: cash on hand minus unpaid cash bills due before the next paycheck. Card bills are excluded — they never touch checking. A "This month" strip adds Cash on hand, Paid this month, and Still due this month.

A forecast from your own schedule

Your payday pattern is stored as data — anchor date plus pattern — never hardcoded. The plan view projects your cash balance day by day from paydays and bill due dates, and flags the lowest point before the next payday.

Bills board

Every bill with its due date, autopay status, and last-paid date. A "due before next paycheck" strip answers the only question that matters mid-month.

Debt tracker

Balances, APRs, minimums, and payoff order with progress bars — plus totals for monthly minimums and estimated monthly interest.

Transfers done right

A card payment is one transfer, checking → card. Never two unlinked one-sided transactions drifting apart.

Why "AI-forward"?

Most budgeting apps are built for eyes. This one is built for reasoning — yours and your assistant's:

  • A small, documented SQLite schema an agent can query directly to answer "what do I owe before Friday?"
  • Categorization as a learning loop: payee rules accumulate with use counts, auditable and improvable over time
  • Every action the UI uses is a plain HTTP endpoint (POST /api/<action>) — the same surface an agent uses
  • Bank sync is a swappable provider: Plaid today, anything tomorrow. Read-only by design — the app never moves money

Run it yourself

git clone https://github.com/rglusic/budget-tracker.git
cd budget-tracker
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python app.py   # http://127.0.0.1:5000

Set SYNC_PROVIDER=plaid with your Plaid credentials in the environment for live bank sync, or seed data via POST /api/import_seed. The repo ships with zero personal data — everything real enters through your own database, which never gets committed.

Principles

  • Money math in integer cents. No floats.
  • Never display a number without saying how fresh it is.
  • No invented data — the app only knows what you import or sync.
  • Read-only toward banks. Payments happen in your bank's app.
